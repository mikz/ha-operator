# 0.1.5: Native window policy inputs

Window policies can now qualify a numeric source or admit a timed episode
without helper clocks and periodic synchronization automations. Configure these
inputs through the existing policy forms. Resource and policy IDs stay stable.

Numeric inputs retain qualification across unknown reports and require fresh
finite evidence after recovery. Timer inputs save absolute request expiry;
pause, cancel, and replacement suppress the affected episode. A running-HA entry
reload interrupts timer episodes before a replacement worker starts.

Covers can monitor an unconfirmed return through raw feedback. The operational
**Effective expiry** and **Return overdue** entities support native history and
dashboards. Internal input state uses diagnostic entities that default disabled.
Desired, observed, and reason entities remain operational.

Existing helper-based configurations remain supported. The
[migration procedure](../migration.md#replace-window-policy-helpers) copies
configuration and starts fresh clocks; it imports no helper state or history.
The package lab exercises native configuration, restart and crash recovery,
expiry, manual precedence, raw confirmation, and encrypted HomeKit commands on
both supported HA versions. Performance measurements and their limits are
documented in [Measure event handling](../performance.md).
