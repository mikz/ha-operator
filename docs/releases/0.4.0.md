# 0.4.0: native policies and typed resources

This candidate requires Home Assistant 2026.10.2 and explicit pre-upgrade
preparation. See [native policy migration](../native-policies.md#upgrade-from-030)
before installing it over 0.3.0. Release acceptance remains recorded separately
with the exact ZIP hash; this document does not establish a packaged lab pass.

Policies use native HA conditions. State conditions are continuous; occurrence
conditions apply once at admission, including external submissions. Optional native
triggers can admit one request with a fixed expiry per policy, with optional native
cancellation triggers. Native pending waits follow HA lifecycle semantics.
The custom numeric qualification and timer episode machines are removed.

Number and select resources use existing native actors through the same worker,
arbitration, request, lease, and confirmation paths. Numeric intent is bound to the
actor's HA service unit. Unit drift inhibits comparison and commands; values are
never converted, clamped, or snapped automatically. Select targets preserve exact
native options. Actor feedback confirms the setpoint or selected option, not a
physical result such as room temperature.

Health calculations now belong to independently configured HA sensors/helpers.
Migrate their consumers and clear old Health checks before upgrade. The migration
rejects residual configuration before mutation, preserves unrelated saved intent
and identities, and retains retired entity registry entries and history.

After a successful configuration-version migration, rollback requires a matching
pre-upgrade native HA backup, including component, entry version, subentries, and
Store. Native restore restarts HA and returns to that snapshot. Restoring old
configuration field shapes alone cannot downgrade the entry version.
